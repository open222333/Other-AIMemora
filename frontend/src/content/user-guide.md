# MEMORA 使用教學

MEMORA 是你自己架設的「AI 共用記憶」。你把偏好、專案背景、知識和決策整理成一筆筆記憶，再授權給 ChatGPT、Claude、Gemini 等 AI 讀取。換 AI、開新對話，都不必重新介紹自己。

這份教學依照使用順序說明：先整理記憶，再讓 AI 使用，最後是權限、安全與備份。

## 快速開始

1. **登入**：帳號預設是 `admin`。密碼是你在 `.env` 設定的 `MEMORA_ADMIN_PASSWORD`；如果留空，初始密碼會印在 API 容器的日誌裡（`docker compose logs api`）。
2. **更改密碼**：到「Settings → Security」設定新密碼，至少 8 個字元。
3. **選擇主題**：右上角的螢幕圖示可切換 Light（淺色）、Dark（深色）、System（跟隨系統）。設定會存在你的帳號，換裝置登入也會套用。
4. **新增第一筆記憶**：到「Memories」按「新增記憶」，或從檔案匯入既有資料（見[匯入與匯出](#匯入與匯出)）。
5. **讓 AI 讀取**：到「Developer → API」建立 API Key，交給 AI 或自動化工具使用（見[讓 AI 使用記憶](#讓-ai-使用記憶)）。

> **小技巧**：按 `⌘K`（Windows 為 `Ctrl+K`）可快速跳到任何頁面或切換主題。

## 管理記憶

### 新增記憶

在「Memories」按「新增記憶」，填寫：

| 欄位 | 說明 |
|---|---|
| 內容 | 一筆記憶只寫一件事，例如「偏好使用繁體中文回答」。寫得具體，AI 越好用 |
| 分類 | 見下方分類表 |
| 標籤 | 用逗號分隔，例如 `memora, backend`。可用來篩選與搜尋 |
| 可信度 | 0–1。你很確定的事填 1；推測或可能改變的事可以填低一點 |
| 到期日 | 選填。短期資訊（例如「下週要交報告」）設定到期日 |
| 允許讀取的 AI | 哪些 AI 能透過 API 讀到這筆記憶。**不勾 = 只有你自己看得到** |

### 分類

| 分類 | 適合放什麼 |
|---|---|
| Profile 個人背景 | 職業、所在時區、常用工具 |
| Preferences 偏好 | 回答語言、語氣、格式偏好 |
| Projects 專案 | 進行中專案的目標、架構、進度 |
| Knowledge 知識 | 長期有效的事實與知識 |
| Decisions 決策 | 已經確認的決定，以及原因 |
| Technical 技術 | 環境設定、版本、硬體規格 |
| Temporary 暫時 | 短期資訊，建議搭配到期日 |

### 編輯與版本歷史

點任一筆記憶，右側會打開詳細面板，可以編輯、封存或刪除。

- 每次修改內容、分類、標籤或可信度，都會產生**新版本**。舊內容不會消失，可在「版本歷史」分頁查看是誰、在什麼時候、因為什麼原因修改。
- 編輯時可以填寫「變更原因」，會記錄在版本歷史中。

### 封存與刪除

| 操作 | 效果 | 適合情境 |
|---|---|---|
| 封存 | 保留資料，但 AI 不會再讀到 | 過時但想留紀錄的資訊 |
| 刪除 | **永久刪除**，連同版本歷史、向量索引一起刪除，無法復原 | 不想留下任何紀錄的資訊 |

### 批次操作

在列表勾選多筆記憶後，右上方會出現「封存」與「刪除」按鈕。換頁或改變篩選時，勾選會自動清除，避免誤刪畫面外的資料。

### 重複偵測

新增、修改或匯入時，如果內容和既有記憶相同（忽略大小寫與多餘空白），系統會拒絕並提示「查看既有記憶」。

## 搜尋記憶

「Memories」頁的搜尋框旁有模式選單：

| 模式 | 用途 |
|---|---|
| 列表篩選 | 依內容文字、狀態、分類、來源篩選，可排序與分頁 |
| 智慧搜尋（Hybrid） | 同時使用關鍵字與語意相似度，依相關性排序。**AI 搜尋記憶時用的就是這個** |
| 關鍵字搜尋 | 只比對文字與標籤。適合型號、版本號、專有名詞，例如 `RTX 4090` 不會被當成 `RTX 4080` |
| 語意搜尋 | 依意思找相近的記憶，例如搜「回答語言」能找到「偏好使用繁體中文」 |

> 語意搜尋需要啟用 Embedding（預設關閉，資料不會離開你的電腦）。想啟用的話，在 `.env` 設定本機的 Ollama，詳見 README 的「搜尋」段落。未啟用時，智慧搜尋只使用關鍵字。

## 審核

「待審核」頁面集中需要你確認的記憶，核准後才會被 AI 讀到。有三種來源：

1. **AI 新增的記憶**：AI 透過 API 寫入的新記憶，預設先進入待審核。
2. **AI 的修改提案**：AI 想修改既有記憶時，不會直接覆寫，而是建立一筆「修改提案」。點開可以看到原內容與提案內容的對照。
   - **核准並套用**：提案內容寫入原記憶，產生新版本，版本紀錄會註明是哪個 AI 提出、由你核准。
   - **拒絕**：原記憶保持不變。
3. **匯入時選擇「待審核」的記憶**。

> 為什麼要審核？AI 可能在瀏覽網頁時讀到惡意指令（prompt injection），被誘導竄改你的記憶。審核能確保進入共用記憶的內容都經過你確認。如果你只讓自己信任的工具寫入，可以在「Settings → AI 透過 API 寫入的記憶需要審核」關閉這個功能。

## 匯入與匯出

### 匯入

1. 到「Imports」上傳檔案，選擇來源平台與預設分類。
2. 系統解析後先顯示**預覽**：哪些會匯入、哪些和既有記憶重複、哪些列有錯誤。
3. 可取消勾選不想匯入的項目，並選擇「略過重複」或「匯入為待審核」。
4. 按「匯入 N 筆」完成，或按「取消匯入」放棄。

超過 24 小時沒有確認的預覽會自動取消。匯入完成後，暫存的原文會被清除，記憶本身成為唯一的副本。

支援的格式：

**Markdown（.md）**：每個條列項目是一筆記憶；標題如果是分類名稱，會套用到底下的項目；`#標籤` 會轉成標籤。

```markdown
## Preferences
- 偏好使用繁體中文回答 #language
- 回答要簡潔

## 技術
- 使用 Docker Compose 部署 #docker
```

**CSV（.csv）**：需要 `content` 欄位，`category`、`tags` 可省略（多個標籤以 `;` 分隔）。

```csv
content,category,tags
偏好使用繁體中文回答,preferences,language;communication
主要顯示卡是 RTX 4090,technical,hardware
```

**JSON（.json）**：MEMORA 的匯出檔可以直接匯回，也接受簡單陣列。

```json
[
  { "content": "偏好使用繁體中文回答", "category": "preferences", "tags": ["language"] },
  "每行一筆的純文字也可以"
]
```

**純文字（.txt）**：每一行是一筆記憶，套用預設分類。

> ChatGPT、Claude、Gemini 匯出的完整對話紀錄，需要 AI 先從對話中擷取出記憶（規劃於 Phase 2）。目前請先把想保留的重點整理成上面的格式。

### 匯出

到「Storage」頁面：

- **匯出 JSON**：包含所有記憶、標籤、來源、權限與完整版本歷史，可再匯入。
- **匯出 CSV**：方便用試算表瀏覽。內容以 `=`、`+`、`-`、`@` 開頭的儲存格會加上單引號，避免被試算表當成公式執行。

## 讓 AI 使用記憶

### 1. 建立 API Key

到「Developer → API」按「建立 API Key」：

- **代表的 AI**：這把金鑰代表哪個 AI，例如 Claude。它只能讀到「允許讀取的 AI」包含 Claude（或「所有 AI」）的記憶。
- **權限**：讀取、新增 / 修改、刪除分開授權。刪除權限預設不勾，非必要不要給。

建立後，金鑰（`mk_` 開頭）**只會顯示一次**，請立即複製保存。之後可以在同一頁面「輪替」（舊金鑰立即失效並產生新的）或「撤銷」。

### 2. 呼叫 API

API 位址是 `http://localhost:8080/api/v1`，完整文件在「Open API Docs」（`/api/docs`）。

搜尋記憶：

```bash
curl -X POST http://localhost:8080/api/v1/memories/search \
  -H "Authorization: Bearer mk_你的金鑰" \
  -H "Content-Type: application/json" \
  -d '{"query": "回答語言偏好", "limit": 5}'
```

新增記憶（預設進入待審核）：

```bash
curl -X POST http://localhost:8080/api/v1/memories \
  -H "Authorization: Bearer mk_你的金鑰" \
  -H "Content-Type: application/json" \
  -d '{"content": "使用者正在學習 Rust", "category": "profile", "tags": ["learning"]}'
```

Python 範例：

```python
import httpx

API = "http://localhost:8080/api/v1"
HEADERS = {"Authorization": "Bearer mk_你的金鑰"}

hits = httpx.post(f"{API}/memories/search", json={"query": "專案背景", "limit": 5}, headers=HEADERS).json()
context = "\n".join(f"- {h['memory']['content']}" for h in hits["items"])
print(context)  # 放進給 AI 的系統提示（system prompt）
```

### 3. AI 能做與不能做的事

| AI 可以 | AI 不可以 |
|---|---|
| 讀取「有效」且允許它讀取的記憶 | 讀到待審核、已封存、或沒開放給它的記憶 |
| 新增記憶（預設進入待審核） | 直接覆寫既有記憶（只能提出修改提案） |
| 提出修改提案 | 修改記憶的狀態或「允許讀取的 AI」 |
| 有刪除權限時刪除記憶 | 呼叫管理功能（API Key、匯出、設定、統計） |

> MCP Server 與各 AI 平台的原生連線規劃於 Phase 2，屆時支援 MCP 的 AI 客戶端可以直接連上 MEMORA。

## 隱私與權限

- **最小權限**：新記憶預設「只有你自己看得到」，任何 AI 都讀不到，除非你勾選允許。預設值可以在「Settings → 新記憶預設允許讀取的 AI」調整。
- **「所有 AI」**：勾選後，任何 API Key 都能讀取這筆記憶。只用在不敏感的資訊，例如語言偏好。
- **資料不外流**：MEMORA 預設不會把任何記憶傳到外部服務。只有你自己啟用外部 Embedding 服務（例如 OpenAI）時，記憶內容才會傳給該服務；使用本機 Ollama 則不會離開你的電腦。
- **操作紀錄**：「Developer → Logs」記錄誰（你或哪把 API Key）在什麼時候讀取、新增、修改、刪除了什麼。紀錄只有 ID，不含記憶內容。
- **AI 最後讀取時間**：在記憶的詳細面板可以看到這筆記憶最近一次被 AI 讀取的時間。

## 帳號安全

- **登入狀態**存在瀏覽器的 httpOnly cookie，網頁程式讀不到，降低被惡意腳本竊取的風險。
- **登出**（右上角頭像 → 登出）：登出目前這個瀏覽器。
- **登出所有裝置**（Settings → Security）：所有瀏覽器的登入立即失效。懷疑帳號外洩，或在公用電腦登入過時使用。API Key 不受影響。
- **變更密碼**：其他裝置會被登出，目前這個瀏覽器保持登入。
- **登入失敗太多次**：同一帳號或 IP 在 5 分鐘內失敗 10 次會暫時封鎖，等待提示的秒數後再試。

## 儲存與備份

「Storage」頁面顯示資料庫、pgvector、Embedding 狀態與各資料表大小。

建議定期備份：

- **匯出 JSON**：最簡單，可再匯入 MEMORA。
- **完整資料庫備份**：在專案資料夾執行

```bash
docker compose exec db pg_dump -U memora memora > memora-backup.sql
```

## 常見問題

**AI 說找不到我的記憶？**
依序檢查：記憶的狀態是否為「有效」（待審核、已封存的 AI 讀不到）；「允許讀取的 AI」是否包含該 AI 或「所有 AI」；API Key 是否有讀取權限、是否已撤銷或過期。

**為什麼 AI 新增的記憶沒有出現在列表？**
它在「待審核」裡。核准後才會變成有效記憶。

**語意搜尋沒有作用？**
預設未啟用 Embedding，系統只使用關鍵字搜尋。啟用方式見 README 的「搜尋」段落；啟用後到「Storage」按「補建向量」，為既有記憶建立索引。

**刪除的記憶可以救回來嗎？**
不行，刪除是永久的。如果只是暫時不用，請改用「封存」。

**畫面顯示「MEMORA API 目前無法連線」？**
後端 API 沒有啟動。在專案資料夾執行 `docker compose logs api --tail 50`，以 `[MEMORA]` 開頭的訊息會說明原因與修正方式；更多情況請見 README 的「疑難排解」。
